# 任务：修正金沙江流域气候数据集的验证口径与网格分辨率问题（v1 → v2）

## 0. 背景
金沙江流域（宜宾以上，约 47.6 万 km²）生态环境评估项目，需要一套 1990–2025 年的流域气候数据用于 SCI 论文。
当前 v1 数据已写入 PostgreSQL，但存在两个**科学口径问题**，请你在 v1 基础上产出 v2，**不要改动 v1 的表**。

## 1. 环境与硬性约定
- 数据库：PostgreSQL；连接串**只从环境变量 `JINSHA_DSN` 读取**（形如 `postgresql://user:pass@host:port/db`），禁止硬编码账号密码；驱动用 psycopg2
- 表名是中文，SQL 里一律用双引号包裹，例如 `"金沙江气候月值_v2"`
- v2 新表统一加后缀 `_v2`；**禁止 DROP / TRUNCATE 任何已有 v1 表**
- 所有脚本必须**幂等**（可重复执行，先建表 IF NOT EXISTS，再按年/月分段删旧插新）
- 每张表都要填 `source`（数据产品全名+版本）与 `updated_at`
- 批量写入用 `COPY` 或 `executemany`，不要一条 INSERT 一行
- 每步打印进度（已处理多少站/格点/年月），便于观察
- **不要为了"结果好看"去调参凑 r 值**；精度低就如实报告并解释原因

## 2. 现有 v1 表（只读，不要改）
- `金沙江格点月值`(lat, lon, year, month, temp_c, precip_mm, et_mm, grid_elev_m, w_coslat, source, updated_at)：195 个 **0.5°** 格点 × 1990–2025 × 12 月 = 84240 行
- `金沙江气候月值`(station, station_id, year, month, temp_c, precip_mm, et_mm, temp_c_raw, grid_elev_m, station_elev_m, source, updated_at)：21 行站（20 站 + `流域面平均`）
- `金沙江气候年值`、`金沙江气候趋势`、`金沙江交叉验证`
- 视图 `金沙江格点面平均月值`、`金沙江流域年值`（按 `w_coslat` 面积加权）
- `站点实测`(station, station_id, year, temp_c, precip_mm, et_mm, temp_raw_c, ghcn_id, ghcn_dist_km, ghcn_elev_m, n_tdays, n_pdays, source, updated_at)：1990–2024；**来源是 GHCN-Daily 最近站代理；`et_mm` 实际是 Hargreaves ET0（潜在蒸散），不是实测蒸散**
- `站点`(站点ID, 名称, 英文, 类型, 经度, 纬度, 海拔)：20 个水文站/电站/生态站

## 3. 问题一：ET 验证口径错误（必须修）
**现象**：`金沙江交叉验证` 里 `variable='et_mm'` 的 20 行，平均 r = 0.141、RMSE = 473 mm、bias = −463 mm。

**根因**：拿 **Hargreaves ET0（潜在蒸散，年 900–1350 mm）** 去和 **MERRA-2 EVLAND（实际蒸散 AET，年 590–880 mm）** 做逐月点对点相关。ET0 是大气蒸发需求上限，AET 受水分供应限制，两者本就不应高相关——r 低是**口径错**，不是数据错。

**要求：拆成三套各自成立的检验，并新建 `"金沙江et口径说明_v2"` 记录定义**

1. **ET0 对 ET0（这才叫验证）**
   - 参考值：ERA5-Land 潜在蒸散（`potential_evaporation` 取负号），或由 ERA5-Land 气温/辐射/风速按 FAO-56 Penman-Monteith 计算 ET0
   - 与 `站点实测.et_mm`（Hargreaves ET0）逐月比较
   - 写入 `"金沙江交叉验证_v2"`，`variable='et0_mm'`，`mode='raw'`，`ref_product` 填实际用的产品
2. **AET 用流域水量平衡检验（不做逐站相关）**
   - 年尺度：AET_obs ≈ P − Q，Q 为流域出口年径流深（金沙江多年平均约 300–350 mm，请用可查证的文献值并标注来源；若无实测径流序列，就明确写"采用文献值 X mm，来源：…"）
   - P 取 `金沙江流域年值` 的面平均年降水；AET_re 取面积加权格点 AET 年值
   - 写入 `"金沙江水量平衡检验_v2"`(year, p_mm, q_mm, aet_obs_mm, aet_re_mm, diff_mm, rel_pct, source)
   - 报告多年均值差与相对偏差（%）
3. **AET 多产品交叉比对**
   - 若可获取 MOD16A2（GEE `MODIS/061/MOD16A2`，500 m、8 天合成，按年求和/平均）或 PML-V2，与 MERRA-2 EVLAND 做**年尺度**比较
   - 写入 `"金沙江et产品比对_v2"`(year, merra2_aet, mod16_aet, diff_mm, r, bias, rmse, source)
   - 拿不到就如实说明并跳过，**不要编造数据**

**论文口径结论要能这样写**：ET0 用于气候干湿/蒸发需求分析，AET 用于生态耗水分析，二者不混用、不互相"验证"。

## 4. 问题二：0.5° 网格太粗，站点落同格（必须修）
**现象**：`金沙江气候月值` 中 屏山 与 向家坝 的降水**逐月完全相同**（如 1990-01 都是 15.8 mm），温度只因两站海拔不同、高程订正量不同才略有差异。原因是 NASA POWER MERRA-2 为 **0.5°（约 50 km）** 网格，相距 <50 km 的站被并进同一格。
后果：把同源数据当独立样本做验证，虚高样本量，审稿必问。

**要求**

1. **换 0.1° 产品重算格点月值**，优先 **ERA5-Land**
   - 获取方式二选一：GEE `ECMWF/ERA5_LAND/HOURLY` 聚合到月；或 CDS API `reanalysis-era5-land-monthly-means`
   - 变量：`2m_temperature`、`total_precipitation`（注意 ERA5 是累计值，需按小时累加并转 mm）、`potential_evaporation`、`u/v_component_of_wind_10m`、`surface_solar_radiation_downwards`、`surface_pressure`
   - 写入 `"金沙江格点月值_v2"`，**新增 `cell_id` 列**（形如 `E100.05_N28.05`，用格点中心经纬度命名），保留 `grid_elev_m`、`w_coslat`
   - 0.1° 约 11 km，20 站基本可分到不同格点
2. **同格诊断**：新建 `"金沙江站点格点映射_v2"`(station, station_id, lon, lat, station_elev_m, cell_id, n_stations_in_cell, is_duplicate_cell, duplicated_by)
   - 把落在同一格点的站标出来；0.1° 下若仍有并格，如实说明，并只保留 1 个代表站参与验证
3. **交叉验证按独立格点重做**：`"金沙江交叉验证_v2"` 增加 `cell_id`、`is_independent` 两列；统计时**只用 `is_independent = true`** 的行；报告里给出「20 站 → N 个独立格点」
4. **温度高程订正保留**（v1 这套很成功：RMSE 3.79→1.08℃，bias −3.50→+0.21℃，r 平均 0.80，请沿用 6.5℃/km 直减率）
5. **降水需处理系统性低估**：v1 的 bias = −127 mm（约 −15%），是 MERRA-2 在横断山区低估地形降水所致，ERA5-Land 同样偏低。请做**分位数订正或按高程分带的比例订正**（说明方法），并把订正前后指标都保留（`mode='raw'` / `mode='corrected'`）
6. 面平均一律按 `w_coslat` 面积加权，权重基于新网格重算

## 5. 附带问题三：验证站独立性（一并处理）
`站点实测` 的 20 个站实际只对应 **7 个 GHCN 源站**：CHM00056146 / 56257 / 56444 / 56492 / 56571 / 56651 / 56671。代理距离最远的是 岗拖 134 km、雷波 117 km、巴塘 112 km。这属于**最近站代理**，不能代表站点真实气候，高海拔站尤其严重。

**要求**

1. 新建 `"金沙江验证站质量_v2"`(station, station_id, ghcn_id, ghcn_dist_km, ghcn_elev_m, station_elev_m, elev_diff_m, n_stations_sharing_source, quality_flag)
   - 质量分级：`dist ≤ 30 km 且 |Δelev| ≤ 300 m` → `good`；`dist ≤ 80 km 且 |Δelev| ≤ 800 m` → `fair`；其余 → `poor`
2. 每个 GHCN 源站只保留**距离最近**的 1 个站作代表，其余站标注 `duplicated_by = <代表站名>`
3. 正式验证只用 `good` + `fair` 且非重复的站；`poor` 站在论文里列为「参考」，或直接剔除
4. 输出一句话结论：**可用于验证的独立站点数 = ?**
