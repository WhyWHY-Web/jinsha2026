> 目标：三人三台电脑，共用同一个后端数据库；数据真实、充实、可自动更新；最终写 SCI 论文（对标 RSEI + GEE 那篇洱海论文）。

## 一、结论：现在的 `jinsha-pg` 能不能直接用？

**不能直接让另外两台电脑连上。** 你截图里的 `jinsha-pg` 是 Docker 里的本地 PostgreSQL 容器，端口 `5432` 只绑定在**你这一台电脑的 127.0.0.1** 上，另外两台电脑访问不到它。

数据库本身是好的——里面有 19 张表、GEE 遥感 3.3 万行数据。缺的是"让三台电脑都能连"的方式。

### 两个可行方案

| 方案 | 说明 | 优点 | 缺点 | 推荐度 |
|---|---|---|---|---|
| **A. 云 PostgreSQL**（腾讯云/阿里云 RDS，或 Neon） | 把库迁到云端，三台都连同一个公网 DSN | 数据不依赖某一台电脑常开；SCI 数据安全持久；随时可访问 | 可能要花点钱（学生价很低） | ⭐⭐⭐ 首选 |
| **B. Tailscale 组网 + 现有容器** | 三台电脑装 Tailscale 组成虚拟局域网，直接连 `jinsha-pg` 那台机器 | 免费、零迁移、数据留在本地 | 数据库所在电脑得开机；跨网需组网软件 | ⭐⭐ 备选 |

**建议用 A（云 PG）**：SCI 论文的数据要长期存、可复现，不能绑定在某个人电脑上。

## 三、三人分工（对齐 RSEI + GEE 论文）

那篇洱海论文的核心方法论是：**RSEI = f(绿度 NDVI、湿度 WET、干度 NDSI/IBI、热度 LST)**，用 PCA 合成，做 1999–2019 五期时序 + 空间自相关（Moran's I、LISA）。

我们金沙江流域照这个框架，三人这么分：

| 同学 | 负责方向 | 核心数据 | 写入数据库的表 | 论文中的角色 |
|---|---|---|---|---|
| **A** | 遥感生态指数（RSEI） | Landsat 5/8/9 地表反射率 → NDVI/WET/NDSI+IBI/LST → PCA 合成 RSEI，多期时序 | `rsei_annual`、`rsei_components`、`遥感月值/年值` | 论文主体（图/表/结论） |
| **B** | 气候水文 + 站点实测 | ERA5-Land / CMFD 气温降水蒸散（逐月长时序）、径流水位、20 站实测校验 | `气候月值/年值/趋势`、`hydrology`、`station_obs` | 驱动因子 + 交叉验证 |
| **C** | 土地利用/人类活动 + 空间分析 + 数据调度 | 土地利用（ESA CCI / CLCD）、夜间灯光（NPP-VIIRS）、人口（WorldPop）；Moran's I / LISA；建表、质检、定时同步 | `lulc`、`nightlight`、`population`、`moran_lisa` | 人类活动分析 + 空间自相关 + 基础设施 |

**各自把数据写进同一个云库，A 的数据表由 A 建，B 由 B 建，C 统一做 schema 规范和数据质检。**

## 四、"真实 + 充实 + 实时更新"怎么落地

### 数据"庞大充实"的量化目标
- RSEI：金沙江流域（约 34 万 km²）**至少 6 期**（1990/2000/2005/2010/2015/2020/2025），30m 栅格逐像元 = 每期约 3700 万像元，分区统计后存库。
- 气候：**逐月 1990–2025** = 420 个月 × 20 站 + 流域面平均。
- 土地利用：**逐年 1990–2023**（CLCD 产品直接有）。
- 总数据量目标：**百万行级**（当前 3.3 万行，扩到 100 万行以上）。

### "实时更新"的诚实分级（生态遥感没有"每秒实时"）
| 数据 | 更新频率 | 实现方式 |
|---|---|---|
| 站点实测（水位/气象） | **逐时**（若接传感器 API） | 定时任务每 1 小时拉一次 |
| MODIS NDVI/LST | **8–16 天** | 每 8 天自动同步 |
| 气候再分析（ERA5/CMFD） | **逐月**（滞后 2–3 月） | 每月 1 号同步 |
| Landsat/RSEI | **逐季/逐年** | 每季/每年合成一次 |
| 土地利用/夜间灯光 | **逐年** | 每年更新 |

**做法**：C 同学用定时任务（Windows 计划任务 / 服务器 cron，或 WorkBuddy 定时自动化）把上面这些同步脚本设成自动跑，实现"到点自动更新、时间戳自动刷新"。

## 五、三人各自的完整提示词（直接复制给大模型用）

### 提示词 A（遥感 RSEI 同学）

```
你是一名遥感生态评估专家。请帮我用 Google Earth Engine (GEE) 计算金沙江流域的遥感生态指数（RSEI），
并输出可直接运行的 GEE JavaScript 或 Python API 代码 + 建表 SQL。

【研究区】金沙江流域（Jinsha River Basin），经纬度范围：经度 97.6°E ~ 105.4°E，纬度 25.9°N ~ 32.5°N。
请用这个矩形范围作为研究区（可用流域矢量边界进一步裁剪，若没有边界就先用矩形）。

【核心方法（严格照抄 RSEI 标准做法）】
RSEI 由四个分量合成，用主成分分析(PCA)取第一主成分 PC1：
1. 绿度 Greenness = NDVI = (NIR - Red) / (NIR + Red)
2. 湿度 Wetness = WET（Landsat 缨帽变换的湿度分量）
3. 干度 Dryness = (NDBSI + IBI) / 2，其中
   - NDBSI = (SI + IBI) / 2，SI = [(SWIR1 + Red) - (NIR + Blue)] / [(SWIR1 + Red) + (NIR + Blue)]
   - IBI（建筑指数）= [2*SWIR1/(SWIR1+NIR) - (NIR/(NIR+Red) + Green/(Green+SWIR1))] / [2*SWIR1/(SWIR1+NIR) + (NIR/(NIR+Red) + Green/(Green+SWIR1))]
4. 热度 Heat = LST（地表温度，单通道算法，需大气参数）
先用水体掩膜 mNDWI = (Green - SWIR1) / (Green + SWIR1) > 0 的水体像元剔除。
各分量分别归一化到 0~1 后做 PCA，取 PC1，再归一化到 0~1 得到 RSEI。

【数据源】Landsat Collection 2 Tier 1 地表反射率：
- Landsat 5 TM: LANDSAT/LT05/C02/T1_L2（1990、1995、2000、2005、2010）
- Landsat 8 OLI: LANDSAT/LC08/C02/T1_L2（2015、2020）
- Landsat 9 OLI-2: LANDSAT/LC09/C02/T1_L2（2023、2024、2025）
每年选同期（建议 10~12 月旱季或 1~2 月）云量最少的影像做年度合成，云用 QA 波段掩膜。

【输出要求】
1. 对每一年，输出整个流域的 RSEI 均值、以及 NDVI/WET/NDBSI/LST 四个分量的流域均值，按行政区或子流域分区统计。
2. 生成一张逐年 RSEI 均值折线图的数据。
3. 给出建表 SQL，表结构如下（数据库是 PostgreSQL，schema 用 public）：
   - rsei_annual(year int, rsei_mean numeric, ndvi_mean numeric, wet_mean numeric, ndbsi_mean numeric, lst_mean numeric, valid_pixels bigint)
   - rsei_components(year int, band varchar, mean numeric, std numeric)
4. 给出把结果写入 PostgreSQL 的连接与插入代码（连接串我会替换成我们自己的云库 DSN）。

【质量要求】必须能复现；注释每一步；说明 PCA 是在像元尺度还是区域尺度做的；给出 RSEI 的取值范围检查（应为 0~1）。
请先输出算法步骤说明，再输出完整可运行代码和建表 SQL。
```

3. 输出交叉验证结果的对比表。

【质量要求】数据必须真实、可追溯来源；注明每个变量的单位和数据源名称；注明更新到哪一年哪一月。
请先说明数据源选择理由，再输出完整可运行 Python 代码和建表 SQL。
