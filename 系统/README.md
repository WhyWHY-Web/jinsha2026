# 金沙江流域森林生态环境智能评估系统

## 一、启动

双击 Windows 单文件版「金沙江生态评估_完整版.exe」自动打开浏览器。默认端口为 8080，端口占用时自动顺延。已初始化的本地账号继续使用原密码。首次初始化的账号密码由启动窗口显示，可在渲染设置中修改。

从源码启动需要 Python 3.10 或更高版本。进入本目录，执行：

```powershell
python -m pip install -r requirements.txt
python boot.py
```

也可通过「启动.bat」或「jinsha2026.cmd」进入同一启动流程。命令行改密使用「python server.py --set-password」。

本地服务的 Swagger 文档位于实际端口下的「/docs」。三维地图和内置分析使用随程序提供的数据。详细变更与验证见 [重构交付](docs/重构交付.md)。

以下保留早期版本的演进记录。

## 二、这一版做了什么



### 0. 本次（10-23 晚）针对反馈的修改

- **框架原样保留**：左侧模型资产库 / 渲染控制台 / 智能体，中部三维，底部剖面 + 模拟运行中心，顶部导航，二维卫星地图全部保留。
- **地形比例真实**：纬度比例由 78.7 校正为 102.5（原来南北被压扁约 30%），高度基准改为 1 世界单位 ≈ 1.08 km，默认垂直夸张 2.2×（可在渲染控制台 1–5× 调）。
- **水位真实**：默认 400 m，只淹没干流最低谷底，不再出现 1500 m 的大面积“淹城”。
- **沿江漫游不抖**：漫游曲线高度做 5 点滑动平均，视线改为阻尼跟随，消除逐帧上下跳动。
- **后端真正在线**：补齐 `/api/legacy/stations`、`/api/eco-services`、`/api/eco-assess`、`/api/db/tables`、`/api/tasks`、`/api/llm/plan`，顶部状态显示「实时 · 时:分:秒」，智能体派发任务不再报“后端离线”。
- **性能**：渲染倍率上限 1.5，Intel Iris Xe 集显 1600×900 稳定 60 FPS。
- **气候换成真实再分析**：接入 NASA POWER（MERRA-2），20 站 × 2000–2024 逐年气温/降水/蒸散，
  按 6.5 ℃/km 直减率从格点高程订正到站点高程；评估指标的气候输入由「参考值」改为实测序列均值，
  并新增「气候年值」「气候趋势」两张可查询表（500 + 20 行）。

### 1. 数据真实性

| 项 | 旧版 | 本版 |
|---|---|---|
| 三维地形 | 站点海拔插值 + 分形噪声（程序合成） | **Terrarium/SRTM 真实高程**，1024² 网格，143–7317 m |
| 坡度/起伏度 | 由噪声地形推算 | 由真实 DEM 逐站计算 |
| 水系 | 手工概化折线 | **DEM 洼地填充 + D8 汇流累积**提取，365 条折线 |
| 站点海拔 | 手工填写，部分与实测不符 | 由 DEM 双线性采样，内部一致 |
| 土地覆盖 | 无 | **Sentinel-2 10 m LULC**（Impact Observatory/Esri），5 km 缓冲统计 |
| 指标口径 | 数值无出处 | 每项标注「实测 / 派生 / 参考 / 估算」，公式在「方法」页公开 |

所有字段都带来源标记，界面不把估算值说成实测值。

### 2. 图像真实性

- 三维贴图为 **Esri World Imagery 2048² 真实镶嵌影像**（≈380 m/px），与 DEM 严格同经纬度范围对齐。
- 山体阴影由真实高程梯度计算（方位角 315°、高度角 42°），不是装饰性噪点。
- 新增「影像绿度 GLI」指标：直接统计每个站点 6 km 窗口内的**真实像元**，
  与土地覆盖推算的植被覆盖度做「空天校验」，当前 **r ≈ 0.89、R² ≈ 0.69**（20 站）。
- 底图版权与分辨率在登录页、数据页、方法页三处标注。

### 3. 评估功能：全面但收拢

按《生态环境状况评价技术规范》HJ 192—2015 的框架计算：

```
EI = (0.35·ABI + 0.25·VCI + 0.15·WRI + 0.15·(100−LSI)) / 0.90
```

- 生物丰度 ABI、植被覆盖 VCI、水网密度 WRI、土地胁迫 LSI 四项分指数；
- 污染负荷因缺数据**明确未纳入**，并按 0.90 归一，避免与官方值误比；
- 风险 `R = 0.42·滑坡 + 0.33·退化 + 0.25·土地胁迫`，分级 58 / 45；
- 评估页收敛为 5 个页签：总览 / 指标 / 权重 / 空天校验 / 情景；
- 决策支持：基准、退化管理、生态修复三情景对比 + 优先治理 5 站清单。

### 4. 页面

- 统一深色设计系统（单一强调色、1px 分隔线、无彩虹渐变），三维场景为主体，右侧单面板；
- 技术路线图独立全屏呈现，严格对照导师流程图的「数据层—模型层—应用层」三层结构，
  节点标注真实完成状态并可点击跳转；
- 登录页使用真实卫星影像做背景，账号密码 + 记住登录 + 错误提示 + 加载态。

### 5. 三维性能

- 单场景、单地形网格、单次绘制：448² 网格（≈40 万三角面），像素比上限 1.5；
- 等高线默认关闭（开启后按距离淡出），避免远景观感噪点；
- 帧率监测：连续低于 38 FPS 自动降到 1.0 倍渲染，低于 28 FPS 自动降到 352² 网格；
- HUD 每 220 ms 更新一次，不在每帧写 DOM。

实测：Intel Iris Xe 集显 / 1600×900 / 448² 地形，稳定 **60 FPS**（软件渲染环境下约 20 FPS，已由自适应降级兜底）。

### 6. 数据接入（解决「不支持手动添加」）

- 「数据 → 新增站点」：输入名称与经纬度，服务端**实时**采样 DEM 高程与坡度，
  并联网补齐土地覆盖（离线则标注「待补」）；
- 「导入 CSV」：批量新增/更新，自动重算指标；
- 「导出」：`/api/export.csv`，含来源字段，可直接喂给山海鲸等大屏工具；
- 所有变更写入 `data/stations.json` 与审计日志，版本号随之更新。

**① 区域级数据治理（后端"指定区域手动调数据"）**

- 新增「区域治理」模块：全流域 / 上游·中游·下游河段 / 7 个气候地貌分区 / **卫星图上框选的自定义区域**；

  结论是"疑似待复核"，可"采纳建议值"或"已核查维持原值"，两条路径都留痕。

### 9. 本次（11-16 晚）新增：态势总览 + 证据分级 + 交叉验证

**① 态势总览（登录后的默认页，`web/assets/home.js`）**

打开系统第一眼不再是模型列表，而是一屏结论：EEI 与等级、三大河段分异、11 年 NDVI 显著退化站、
按「风险 0.55 + 趋势 0.28 + 待复核 0.17」排序的优先核查名单、7 个气候地貌分区的聚合统计、
证据分级条。点站点名直接三维定位，指纹变化 20 s 内自动重算。
所有数字来自 `/api/conclusion` 一次计算，与生态评估、风险预警、巡检建议**同一个引擎**。

顺带支持 `#模块名` 深链（如 `/app.html#data`），答辩时可直接跳页。

**② 证据分级 A/B/C/D（`/api/evidence`）**

16 项指标逐项标注 **A 实测 / B 模型·再分析 / C 遥感反演 / D 代理·经验**，并写清来源、口径、
验证状态。当前 **A1 · B5 · C3 · D7**。D 级不代表错，代表"还没有真值校验"，论文必须注明——
把这件事写进系统而不是藏在文档里，是这一版最想做的事。

**③ 交叉验证（`/api/validate`，`tools/validate.py`）**

NASA POWER vs ERA5-Land（气温）、vs GPM IMERG（降水），量化 r / RMSE / 系统偏差：

| 对比 | r | RMSE | 偏差 | n |
|---|---|---|---|---|
| 气温（订正后） | **0.934** | 2.36 ℃ | −1.50 ℃ | 200 站·年 |
| 气温（订正前） | 0.859 | 4.75 ℃ | −3.99 ℃ | 200 |
| 降水 | 0.892 | 431 mm | +380 mm（IMERG 山区高估） | 180 |

关键方法点：ERA5-Land 的"格点高程"要用 **0.1° 格元内的平均地形**，不是格元中心点。
用中心点时订正反而把 r 从 0.86 拉低到 0.74；改用格元均值后 r 升到 0.934、RMSE 减半。
**这不是调参，是物理量定义问题**——可直接写进论文的数据处理一节。

## 五、已知边界（写在明处，答辩不被动）

1. 地形为 30 m DEM 重采样，不能做米级微地形判断；
2. 土地覆盖为 2017–2021 复合产品，无法反映当年变化；
3. 气候为 MERRA-2 再分析（0.5°×0.625° 格点，2000–2024 逐年），气温已按 6.5 ℃/km
   直减率从格点高程订正到站点高程（原始格点普遍高 50–1850 m）；降水/蒸散为格元面平均，
   山区地形雨可能偏低。格点尺度反映的是区域气候，不能代替站点实测；
4. 站点生态指标是土地覆盖推算的**估算值**，不是样地实测；
5. 滑坡/退化权重为专家经验取值，未做 AHP 一致性检验与敏感性分析；
6. 机器学习（SVM/RF/CNN）因缺标注样本，仅保留接口，**未训练、不参与结果**；
7. 专题层为 20 站 IDW 插值，仅表达空间格局，不代表逐像元实测。

### 实景走廊（近景高精度，沿干流连续）

全域地形是 742 m 网格，缩到 1 km 以下就没有信息量了。**实景走廊**沿干流铺了
39 块互相重叠的高精度补丁（20 个站点 + 19 个相邻站点中点），缩放到近处自动切换：

- 高程 **Copernicus DEM GLO-30，30 m 真实卫星高程**，512² 网格（约 55 m/格）
- 影像 **Esri World Imagery 单张导出 2048²**（约 27 m/px），比逐瓦片拼接快一个数量级
- 每块覆盖 ±0.13°（约 ±28 km），相邻块重叠，整条干流中下游能连续放大不断档
- 相机最近距离放到 **6**（原来锁死 26，所以怎么滚轮都贴不近）
- 近景垂直夸张自动降到 **1.15×**，接近实地观感；光照按 27°N 秋季正午真实太阳高度角布设
- 补丁四周有向下延伸的"裙边"，不会看到漂浮的地板

入口：滚轮放大到任一站点附近即**自动**铺上；或点站点卡「🔍 实景」，「↩ 退出实景」返回。

> 已知边界：走廊只覆盖干流沿线，支流和偏远集水区仍是 742 m 粗网格；
> 补丁高程与全域 742 m 网格平均差约 93 m，差的正是全域平滑掉的山脊沟谷，不是数据错误；
> 整流域无差别 30 m 需要四叉树 LOD 流式加载（全流域约 7 亿格网，不可能一次载入），尚未实现。

数据可用 `python tools/build_detail.py --corridor` 重新生成（会联网取 Copernicus 与 Esri），
39 块约 12 分钟；exe 用 `python tools/pack_exe.py` 重新打包（当前 72 MB）。
