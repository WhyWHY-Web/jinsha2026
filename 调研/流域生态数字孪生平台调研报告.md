# 金沙江流域森林生态数字孪生平台 · 调研报告

> 调研主题：流域森林 / 遥感生态评估方向的数字孪生平台同类案例与可复用交互方案
> 适配对象：金沙江流域森林生态环境 AI 智能评估系统（学科竞赛 + SCI 论文配套演示平台）
> 技术栈锚点：前端 Three.js 三维渲染 · 前后端分离 · 后端独立 server（承载遥感读取 / AI 评估模型计算 / 指标统计）
> 调研范围：**仅**森林、植被、生态质量、生态胁迫方向；**排除**工业、园区、水利防汛、城市安防类孪生
> 日期：2026-11-25

## 二、适配本项目的页面布局方案

金沙江项目已有三维主界面（`web/app.html`）+ 独立数据看板（`web/dashboard.html`）。以下方案以「竞赛答辩演示 + SCI 论文配套截图」为第一目标、兼顾日常科研使用，给出四种布局，均标注优缺点与适配建议。

### 方案 A：大屏指挥式（沉浸三维 + 悬浮面板）—— ★ 首选，答辩/演示

**结构**：全屏 Three.js 三维主视口铺满；面板全部悬浮（浮动卡片），无固定侧栏。

```
┌──────────────────────────────────────────────────────────┐
│ [左上·项目标题+KPI条]         [右上·登录/导出/关于]        │
│  ┌─────────────┐                        ┌──────────┐      │
│  │ 图层控制面板 │                        │ 评估等级  │      │
│  │ ☑地形 ☑河网 │    Three.js 三维主视口  │ 图例(悬浮)│      │
│  │ ☑植被覆盖 ☑胁迫│   (地形+地块着色+点位)│          │      │
│  └─────────────┘                        └──────────┘      │
│  ┌──────────────────────┐   ┌──────────────────────┐       │
│  │ 时序推演控制条(时间轴) │   │ 指标筛选面板(悬浮)    │       │
│  └──────────────────────┘   └──────────────────────┘       │
│      ┌─────────── 底部·评估结果图表抽屉(可折叠) ──────────┐ │
└──────────────────────────────────────────────────────────┘
```

- **优点**：三维沉浸感最强，视觉冲击力大，答辩/演示/论文截图效果好；与 TerraTwin、Forest Digital Twin、广东林草平台的产品形态一致；悬浮面板可折叠，主视口利用率高。
- **缺点**：面板堆叠多时易遮挡三维；信息密度低时显得空；不适合长时间高密度科研操作。
- **适配建议**：作为**默认主页**。图层控制、指标筛选、评估结果图表做成 3 个可折叠悬浮卡片；时序推演条固定在底部通栏；双击三维或按 Esc 进入「纯三维」沉浸态。

### 方案 B：GIS 工作台式（左图层面板 + 中三维 + 右数据抽屉）—— ★ 科研日常操作

**结构**：左侧固定图层面板，中间三维，右侧属性/图表抽屉（点击地块/站点后展开）。

```
┌──────────┬───────────────────────────────┬──────────────┐
│ 图层控制  │                               │ 详情/图表    │
│ 面板(固定)│      Three.js 三维主视口       │ 抽屉(点击后  │
│          │                               │ 展开)        │
│ ☑地形    │                               │ ·地块属性     │
│ ☑河网    │                               │ ·指标明细     │
│ ☑植被覆盖 │                               │ ·时序曲线     │
│ ☑生态质量 │                               │ ·评估等级     │
│ ☑胁迫风险 │                               │ ·证据分级     │
│ [指标筛选]│                               │              │
│ [年份范围]│                               │              │
│ [一键评估]│                               │              │
└──────────┴───────────────────────────────┴──────────────┘
        [底部通栏：时序推演时间轴 / 报告导出 / 返回看板]
```

- **优点**：符合 GIS 从业者心智模型（ArcGIS/QGIS/GeoScene 用户零学习成本）；「图层 + 属性 + 图表」三区职责清晰；适配日常科研的反复筛选、钻取。
- **缺点**：左右固定栏压缩三维视口，演示冲击力弱于方案 A；移动端/小屏适配差。
- **适配建议**：作为**「科研模式」**（顶栏提供「演示模式 / 科研模式」切换）。右侧抽屉改为点击对象后滑出，平时收起以保主视口面积。

### 方案 C：双视图联动式（三维 + 二维/时序对照）—— ★ 论文配图 / 时序推演

**结构**：左右或上下分屏，一侧 Three.js 三维，另一侧二维地图（卫星底图 + 栅格热力）或 ECharts 时序大图，两侧视图联动（框选/缩放/时间轴同步）。

```
┌──────────────────────────────┬───────────────────────────┐
│  Three.js 三维场景           │  二维地图 / ECharts 时序    │
│  (地形+地块着色+点位)         │  (NDVI热力+时序曲线联动)    │
│                              │                           │
│                              │  ┌─────────────────────┐  │
│                              │  │  多年 NDVI 时序曲线   │  │
│                              │  └─────────────────────┘  │
└──────────────────────────────┴───────────────────────────┘
        [共用底部时间轴 / 联动框选 / 指标筛选]
```

- **优点**：三维直观 + 二维精确/时序可读，兼顾「看现象」与「读数据」；论文配图可同时截取二维/三维两套证据；时序推演时二维栅格 + 三维着色同步变化，说服力强。
- **缺点**：屏幕一分为二，单侧视口变小；需额外维护二维视图（Leaflet/Mapbox 或自绘 canvas）与联动状态；开发量最大。
- **适配建议**：作为**「时序推演」专页**（点击顶栏「时序推演」进入），或论文配图的截图模式；二维视图用轻量 canvas 栅格渲染即可，不必引入重地图引擎。

### 方案 D：向导式评估工作流（左侧步骤条）—— ★ 报告生成 / 一键评估

**结构**：左侧竖排步骤条（选区域 → 选指标 → 触发评估 → 查看结果 → 导出报告），中间三维 + 右侧参数，按步骤逐步点亮。

```
┌──────────┬───────────────────────────────────────────────┐
│ ① 选区域  │                                               │
│ ② 选指标  │      Three.js 三维主视口 + 右侧参数面板        │
│ ③ 触发评估│      (当前步骤高亮，已完成步骤打勾)             │
│ ④ 看结果  │                                               │
│ ⑤ 导报告  │                                               │
└──────────┴───────────────────────────────────────────────┘
```

- **优点**：把「框选→筛选→一键 AI 评估→分级着色→导出报告」这条**核心业务链路固化成可见流程**，竞赛评委/论文审稿人能一眼看懂平台逻辑；降低演示出错率。
- **缺点**：强制线性，灵活性差，日常科研频繁操作时繁琐。
- **适配建议**：作为**「一键评估」功能的引导层**（可跳过），而非全局框架；步骤状态与后端评估任务的提交/进度/完成态绑定。

**综合建议**：以 **方案 A（大屏指挥式）为默认主页** + **方案 B 作为「科研模式」**，时序推演与报告导出分别复用方案 C / 方案 D 的专页形态。四种方案的共同底座是「三维主视口 + 图层/指标/图表/时间轴/弹窗」五件套组件，只是排布方式不同。

## 三、Three.js ↔ server 交互数据流（可直接复用）

> 本节是调研重点。所有数据流贴合金沙江「森林生态评估」业务，沿用项目既有约定：后端 REST（`http://localhost:8080/api/...`，纯 JSON），前端 Three.js（Y 轴向上，地形网格 + 地块着色 + 点位精灵/实例化）。指标体系为**植被覆盖（FVC/NDVI/RSEI）· 生态质量（EQI）· 胁迫风险（stress）**，评估等级统一 `优/良/中/差` 四级（绿/蓝绿/黄/红）。

### 3.0 总体架构与统一约定

```
[Three.js 前端]  ──HTTP(JSON)──>  [server.py 后端]  ──>  遥感数据读取
     │  交互(框选/筛选/时间轴/点击)      │ AI评估模型计算
     │  <── 评估结果(地块等级/时序/详情) ─┘ 指标统计(MK趋势/Tennant/RSEI)
     ▼
三维场景同步：地块着色 + 图层叠加 + 点位渲染  ⇄  图表面板刷新
```

**统一返回骨架**（所有接口共用，避免前端反复判空）：

```json
{
  "code": 0,
  "message": "ok",
  "data": { "...": "业务数据" },
  "meta": { "region": "jsj", "crs": "EPSG:4326", "generated_at": "2026-11-25T17:00:00Z" }
}
```

**统一约定**：坐标一律经纬度（EPSG:4326）+ 高程米；前端在「金沙江局部投影原点」处将经纬度转 Three.js 局部坐标（`x = lng→局部东向`、`z = -lat→局部北向`、`y = 高程`）；评估等级与色带映射由**前端统一色板**完成（后端只回等级枚举，不回颜色，保证三维/图表/图例三处颜色一致）。

---

### 3.1 数据流一：流域子区域框选 → 一键 AI 评估 → 地块分级着色（★ 核心链路）

**触发**：用户在地图上拖拽框选（或点击预置子流域 chip），点击「一键评估」。

**前端组装参数**（POST `/api/evaluate`）：

```json
{
  "bbox": [100.5, 26.2, 101.2, 27.0],
  "indicators": ["fvc", "eqi", "stress"],
  "year": 2023,
  "method": "rsei",
  "resolution": 500
}
```

- `bbox`：由 Three.js 框选矩形经「屏幕坐标 → 世界坐标 → 反投影」得到经纬度范围；`indicators`：勾选的生态指标；`method`：评估模型（rsei=遥感生态指数 / 自定义 ML）；`resolution`：后端重采样栅格边长（米），用于控制返回地块数。

**后端处理**：按 bbox 与 resolution 切网格 → 逐格读取遥感产品（FVC/NDVI/胁迫因子）→ 调 AI 评估模型计算 EQI 与综合等级 → 聚合统计。

**返回数据结构**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "task_id": "eval-20261125-0001",
    "bbox": [100.5, 26.2, 101.2, 27.0],
    "grid_cells": [
      {
        "cell_id": "g_12345",
        "lng": 100.52, "lat": 26.31,
        "values": { "fvc": 0.72, "eqi": 0.68, "stress": 0.23 },
        "grade": "良",
        "evidence": "B"
      }
    ],
    "summary": {
      "area_ha": 18520,
      "grade_dist": { "优": 0.18, "良": 0.44, "中": 0.28, "差": 0.10 },
      "mean_eqs": 0.61,
      "trend_note": "近十年 EQI 呈波动上升(MK Z=+2.1)"
    },
    "report_id": "RPT-20261125-0001"
  }
}
```

- `grid_cells`：**分级着色的直接数据源**，每个 cell 携带坐标 + 指标值 + 等级 + 证据分级（A/B/C/D，复用项目既有证据分级体系）；`summary`：供 KPI 卡与图表面板消费；`report_id`：供 3.5 导出。

**三维场景联动逻辑**：

1. 前端收到 `grid_cells` 后，将每个 cell 对应到地形网格上的「地块 patch」：`grade → 色板`（优=绿 `#3B6D11`、良=蓝绿 `#0F6E56`、中=黄 `#EF9F27`、差=红 `#E24B4A`）。
2. 着色方式：**优先用 `BufferGeometry` 顶点色（vertex color）**按 patch 重写颜色缓冲，避免为每格新建 Material（防止 draw call 爆炸）；或对每个 patch 复用同一组 4 个 `MeshBasicMaterial`/`MeshLambertMaterial`，按 grade 索引赋值。
3. 同步：更新评估等级图例（悬浮卡片）→ 刷新底部图表抽屉（等级占比饼图 + 指标均值柱状图，ECharts `setOption` 局部更新）→ KPI 条数字滚动。
4. 撤销/重做：前端保存上一版 `grid_cells` 快照，支持「清除评估结果」恢复原始地形着色。

### 3.2 数据流二：多期遥感影像时序推演

**触发**：底部时间轴拖动 / 播放按钮，年份游标从 `year_start` 滑到 `year_end`。

**前端组装参数**（GET `/api/timeseries`）：

```
/api/timeseries?indicator=fvc&region=jsj&years=2010,2013,2016,2019,2023&format=grid
```

**后端处理**：按年份读取对应期遥感产品 → 重采样到统一网格 → 返回每期栅格值 + 统计。

**返回数据结构**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "indicator": "fvc",
    "grid": { "cols": 120, "rows": 90, "origin": [100.3, 26.1], "cellsize": 0.005 },
    "series": [
      { "year": 2010, "values": [0.41, 0.55, "...", 0.62], "stats": { "mean": 0.53, "std": 0.11 } },
      { "year": 2016, "values": [0.48, 0.60, "...", 0.70], "stats": { "mean": 0.60, "std": 0.09 } },
      { "year": 2023, "values": [0.56, 0.68, "...", 0.77], "stats": { "mean": 0.68, "std": 0.08 } }
    ]
  }
}
```

- `grid` 描述栅格布局（列/行/原点/像元尺寸），`series[].values` 为按行展开的一维数组，前端据此重建二维色场。

**三维场景联动逻辑**：

1. 时间轴拖动时**节流**（如 120ms），只请求当前年份附近的数据，避免每帧打接口。
2. 收到某期 `values` 后，将一维数组映射回网格 → 按 FVC 值域（0–1）映射到绿→棕的**连续色带** → 重写地块顶点色（与 3.1 共用同一套着色管线，区分「分级着色」与「连续渐变」两种模式）。
3. 联动：二维对照视图（方案 C）同步刷新该期热力；时序大图（ECharts）高亮当前年份游标；图例显示当前年份与均值。
4. **预加载策略**：进入推演页时一次性把全部 `series` 拉齐（数据量可控时），拖动只做本地插帧/切换，避免拖一步卡一步；栅格过大时改为按需分年请求 + 缓存。

### 3.3 数据流三：图层叠加控制（河网 / 站点 / NDVI 热力 / 胁迫风险）

**触发**：图层控制面板勾选/取消某项（如「胁迫风险」热力图层）。

**前端组装参数**（GET `/api/layer`）：

```
/api/layer/stress?bbox=100.5,26.2,101.2,27.0&zoom=3
```

**后端处理**：按视野 bbox 与层级，返回对应图层的**简化/切片后数据**（矢量抽稀、栅格重采样）。

**返回数据结构**（分两类——矢量 / 栅格）：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "layer": "stress",
    "type": "raster",
    "grid": { "cols": 80, "rows": 60, "origin": [100.5, 26.2], "cellsize": 0.01 },
    "values": [0.1, 0.3, "...", 0.9],
    "legend": { "min": 0, "max": 1, "label": "胁迫风险指数" }
  }
}
```

矢量图层（河网/站点）则返回 GeoJSON 风格的简化几何 + 属性：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "layer": "stations",
    "type": "vector",
    "features": [
      { "id": "s_shigu", "name": "石鼓", "lng": 100.24, "lat": 26.87, "props": { "type": "水文" } }
    ]
  }
}
```

**三维场景联动逻辑**：

1. 栅格图层：与 3.2 同一条着色管线，作为独立「热力叠加层」铺在地形之上（`polygonOffset` 或轻微抬高 y 避免 z-fighting）；切换时只改该层可见性/颜色，**不重建地形**。
2. 矢量图层：河网沿用项目既有 `hydro.json` 三维线；站点用**实例化（InstancedMesh）或精灵**渲染点位，开/关只切 `visible`；选中站点高亮 + 顶部标注。
3. 性能：图层开关只做 `visible` 切换与必要的颜色重写，**禁止在切换时重新请求整份地形或重建 geometry**；大矢量文件由后端按视野切片返回（复用 3.4 的视野裁剪逻辑）。

### 3.4 数据流四：点位 / 地块详情钻取弹窗

**触发**：点击三维场景中的站点或已着色地块（`Raycaster` 仅在 click 时拾取，不做 mousemove 全量拾取）。

**前端组装参数**（GET `/api/detail`）：

```
/api/detail?type=station&id=s_shigu&year=2023
/api/detail?type=cell&id=g_12345&year=2023
```

**后端处理**：按对象类型与年份返回该对象的指标明细 + 长时序曲线数据（供弹窗内嵌图表）。

**返回数据结构**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": "g_12345",
    "name": "地块 g_12345",
    "lng": 100.52, "lat": 26.31,
    "current": { "fvc": 0.72, "eqi": 0.68, "stress": 0.23, "grade": "良", "evidence": "B" },
    "timeline": {
      "years": [2010, 2016, 2023],
      "fvc": [0.41, 0.56, 0.72],
      "eqi": [0.50, 0.58, 0.68],
      "trend": { "sen_slope": 0.018, "mk_z": 2.1, "p_value": 0.03 }
    }
  }
}
```

**三维场景联动逻辑**：

1. 点击 → 弹窗（悬浮/右侧抽屉）展示 `current` 指标卡 + `timeline` 内嵌 ECharts 时序曲线（含 MK 趋势标注）。
2. 三维中该地块/站点**高亮**：复用材质 + 独立高亮层（或切换 emissive / 加外描边），**不要 clone 材质**。
3. 弹窗内容**按需请求**：对象属性不预先全部挂到前端 mesh 上，仅存 `id` 与 `type`，点击时再拉详情，避免首屏内存膨胀。

### 3.5 数据流五：一键 AI 评估报告导出

**触发**：评估完成后点击「导出报告」（复用 3.1 的 `report_id`）。

**前端组装参数**（GET `/api/report/download`）：

```
/api/report/download?report_id=RPT-20261125-0001&format=pdf
```

**后端处理**：按 report_id 组装报告（封面 + 指标概览 + 等级分布图 + 关键地块时序图 + 证据分级说明）→ 生成 PDF（或 HTML→打印）。

**返回**：`application/pdf` 二进制流（或 `{ "code": 0, "data": { "download_url": "/api/report/file/RPT-...pdf" } }`，免密令牌环境下用带 sid 的下载链接）。

**三维场景联动逻辑**：报告导出为**只读终点**，不反向改三维；但报告内的等级分布图与三维当前着色必须同源（均来自 3.1 的 `grid_cells` 与 `summary`），保证「屏幕所见 = 报告所载」。

## 四、UI 交互借鉴方案（来自同类案例）

1. **图例点击开关图层**（借鉴矿山生态天眼）：图例每一项即图层开关，点一下关闭对应图层样式、再点恢复——比单独「图层面板 + 图例」两处更省空间、更直观。
2. **任意空间位置时序曲线钻取**（矿山生态天眼）：点击三维任意点，弹窗直接给出该点的 NDVI 等指标多年曲线——可移植为金沙江「点击任意地块看 FVC/EQI 时序」。
3. **浏览器内框选多边形 → 后端测地计算**（EcoAtlas）：前端只负责画 GeoJSON 多边形与面积显示，测地面积/质心交给后端——金沙江「框选子区域」应照此把「几何 → 面积/统计」交给 server 计算，前端不硬算。
4. **时间轴驱动植被生长/演变推演**（广东林草平台、TerraTwin、Forest Digital Twin）：底部时间轴拖动 + 播放，三维植被/栅格随时间变化——金沙江「多期遥感时序推演」直接对标。
5. **悬浮统计面板 + AI 助手**（TerraTwin）：KPI 与 AI 问答做成浮动卡片覆盖在三维之上——金沙江已有「智能体」模块可复用此形态，评估结果用自然语言解释。
6. **点击对象弹属性（物种级）**（Forest Digital Twin）：点击树木/地块 → 查指标 + 异速方程/证据说明——金沙江「点击地块查指标 + 证据分级 A/B/C/D」一致。
7. **状态色映射**（TerraTwin 的 verified/pending 彩色圆点）：评估等级、证据分级用一致的小圆点/色块贯穿列表与地图，形成视觉语言统一。

## 五、Three.js 开发联动坑点（检索归纳 + 金沙江落地建议）

| # | 坑点 | 金沙江落地建议 |
|---|---|---|
| 1 | **GIS 坐标轴映射错位**：Three.js Y 轴向上，GIS 平面坐标 X/Y 是水平面 | 统一「经纬度 → 局部坐标」转换函数：`x=局部东`、`z=-局部北`、`y=高程`；河网水面抬升等偏移在此函数内做，杜绝散落各处 |
| 2 | **每帧做 GIS 计算**：把坐标转换/空间查询/属性筛选/射线拾取写进 `requestAnimationFrame` | 渲染循环只留 `controls.update()` + `renderer.render()`；坐标转换、拾取、颜色重写全部改为**事件触发** |
| 3 | **大 GeoJSON / 大栅格一次性渲染**：下载慢、解析慢、内存爆 | 后端**按视野 bbox + 分辨率重采样/抽稀**后再下发（3.1/3.2/3.3 已按此设计）；属性字段裁剪到最小 |
| 4 | **每帧全量 Raycaster 拾取**：mousemove 上全量检测拖慢交互 | 只在 click 时拾取；只对「可交互图层」建拾取对象；复杂模型用简化碰撞体拾取 |
| 5 | **隐藏/移除对象不释放资源**：geometry/material/texture 残留致显存泄漏 | 图层移除/切年份时统一 `dispose()`：`geometry.dispose()`、`material.map?.dispose()`、`material.dispose()` |
| 6 | **频繁 clone 材质高亮**：高亮一次 clone 一次 | 复用材质 + 独立高亮层（emissive/描边），或 4 个预置 grade 材质按索引复用 |
| 7 | **LOD 只做不做空间切片**：首屏仍要整块下载 | 地形按四叉树切块 + 按相机距离换精度；关键：相邻层级边界顶点强制对齐，否则远处地形「龟裂」 |
| 8 | **纹理过大拖慢首屏**：精细影像/倾斜摄影纹理是首屏杀手 | 影像纹理抽稀后再切瓦片；分级着色优先用 vertex color，不贴大纹理 |
| 9 | **z-fighting**：叠加图层与地形共面闪烁 | 叠加热力层用 `polygonOffset` 或轻微抬高 y；水面与地形避免同面 |
| 10 | **不预加载/无缓存**：来回拖时间轴反复请求同一期 | 时序数据进入推演页先整体拉齐（数据可控时），本地插帧；栅格大则分年请求 + 内存/HTTP 缓存 |

## 六、生态评估类平台设计避坑建议

1. **分级色带语义要「生态正确」**：生态评估用 **绿=优/健康、红=差/风险**，与遥感指数（NDVI 绿=植被多）同向，**绝不能用金融「涨红跌绿」习惯**（金沙江是生态评估平台，不是行情看板）。四级建议：优 `#3B6D11`、良 `#0F6E56`、中 `#EF9F27`、差 `#E24B4A`，且三维/图表/图例三处共用同一色板常量。
2. **等级与连续值分离表达**：评估等级（优/良/中/差）用离散色块，植被覆盖度/NDVI 等指标用连续色带；两者是两套着色模式，别混用导致「等级看不清、数值读不准」。
3. **评估结果必须带证据分级**：森林生态评估有不确定性（模型、数据源、时序缺失都会影响），应给每个地块/结论标注证据等级（金沙江已有 A/B/C/D），并在弹窗、报告里显式呈现，避免「一图定生死」的误导，也契合 SCI 论文可复现性要求。
4. **时序推演要处理缺年与插值**：遥感产品常因云量/轨道缺年，后端应标记「实测/插值」并同步到前端时间轴（插值年份用虚线/半透明区分），不要让用户误以为逐年都是实测。
5. **栅格数据后端做金字塔/切片**：绝不把全流域高分辨率栅格一次性给前端；后端按 `resolution`/`zoom` 重采样，控制单次返回 cell 数（如 ≤ 1 万格），否则「一键评估」会卡成假死。
6. **分级着色边界要可解释**：用户框选的子区域边界、评估等级的分级阈值（如 EQI 0.6/0.4/0.2 切四档）应在图例或帮助里给出，供论文/答辩说明口径。
7. **「一键评估」要做进度与异步**：AI 评估可能耗时，避免前端同步阻塞——给出 `task_id` + 轮询/进度（或预计算缓存常用区域），演示时「秒出」、真实算时「可等待」。
8. **报告与三维同源**：导出报告里的图表数据必须与三维当前着色来自同一份 `grid_cells`/`summary`，否则出现「屏幕红色、报告说优」的错位，答辩极易被追问。
9. **河流/水网与生态评估的业务边界**：金沙江河网是生态背景要素，**不进入水利防汛口径**（不做洪水演进、蓄洪调度）；河流只作为「流域范围 + 站点锚点 + 生态流量背景（Tennant）」呈现，避免被误归类为水利孪生。
