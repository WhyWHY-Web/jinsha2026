# 金沙江平台 · 前端实现与交互设计调研报告

> 聚焦：前端渲染方式、页面布局、功能界面排版、模块交互设计
> 依据：金沙江现有前端代码（`系统/web/app.html` 主界面 + `assets/home.js` 态势总览 + `dashboard.html` 数据看板）+ 全网同类前端实现案例
> 输出：参考案例 → 可借鉴点 → 模块交互关系 → 落地建议

---

## 一、现有前端实现盘点（先认清"现在长什么样"）

| 维度 | 现状 |
|---|---|
| 技术栈 | 原生 JS（无框架）+ Three.js r158 + ECharts，单文件 `app.html` 内联 JS 约 8000 行 + 外部模块 `assets/home.js` 等 |
| 页面结构 | `app.html`：顶栏 54px（品牌 + 7 模块 nav + 状态 chip）→ `#layout`（左 `#sidebar` 356px + 可拖拽 `#vsplit` + 中 `#viewPane` 三维 + 底 `#bottomRow` 160px 双面板 + `#hsplit`）+ HUD 层（标题/相机/图例/图层 chips/站点卡片/漫游条）+ `body.maxmap` 最大化 |
| 状态管理 | 全局对象 `G`（`curPh` 当前模块、`curModel`、`roaming`、`exag` 等场景参数）+ `PH_MODULES` 模块注册表 + `window.switchModule/dhFetch/flyToStationIdx/toast/STATIONS` 全局函数 |
| 模块切换 | `switchModule(id)` → 置 `G.curPh` → `renderPh(curPh)` 重绘侧栏面板 |
| 数据链路 | `dhFetch('/api/...')` 统一拉取；`/api/data/version` 每 20s 指纹轮询，token 变化才重绘 |
| 三维联动 | `flyToStationIdx(i)`（面板→相机飞行）；Raycaster 拾取站点 → `#stationCard` 弹属性 +「进入评估」 |
| 信息层级 | `home.js` 态势总览：结论卡（EEI 大数字+等级+风险+证据分级条）→ 干流三段 → 植被趋势 → 优先核查 → 分区聚合 → 多源数据 → 指标体检 → 快捷入口 |
| 证据体系 | A/B/C/D 证据分级 + 能力边界声明（已做得很到位，是亮点） |

**已具备的优势**：深色 Design Token 语义（`--acc/--warn/--bad`）、可拖拽分栏、最大化模式、证据分级、数据指纹防闪、站点定位飞行。

**暴露的短板**（落地建议据此展开）：
1. **色带三处不一致**：`home.js` 的 `gradeCol`（A=#4ade80/B=#a3e635/C=#ffd48a/D=#ff8a8a）与 `evStrip` 证据色（B=#7fe3cd/C=#7ab8ff/D=#ffb03a）不同源；`dashboard.html` 又用金融式 `kpi.up=红/down=绿`；`app.html` CSS 用 `--bad/--warn/--acc`。同一"等级/证据/风险"语义有多套色值。
2. **状态靠手动刷新**：`G.curPh` 变要手动 `renderPh`，数据变要手动 `setInnerHTML`，缺"订阅-通知"。
3. **三维缺时间维度**：`dashboard.html` 有年份双滑块，但三维主界面无"时序推演时间轴"，多期影像对比是 2D/3D 割裂的。
4. **反向联动偏弱**：面板→三维（flyToStationIdx）已通，三维拾取→图表/列表高亮未闭环。
5. **单文件过大**：8000 行内联 JS，模块边界靠函数命名约定。

## 三、可借鉴的设计模式（提炼对齐金沙江）

### 3.1 页面结构 / 信息层级
- **"总-分"三段式**（案例6）：中间三维是"空间态势"，两侧/底部是"数据细节"，扫一眼中间知全局、看两侧知详情。金沙江 `app.html` 已是「左面板 + 中三维 + 底面板」同构，保持即可。
- **结论卡第一屏**（案例6 的"3 秒捕捉" + 金沙江 home.js 已有）：核心结论（EEI/等级/风险/证据分级）必须首屏可见，多源数据、体检等下沉为可折叠区。金沙江 home.js 已做到"结论卡第一屏"，但后续 7 个区块**一次性全渲染**导致 sidebar 过长，建议折叠。
- **交互克制**（案例6）：大屏/答辩场景不加复杂弹窗、树形控件、穿梭框，最多"点击联动 + tab 切换"。

### 3.2 组件关系 / 状态流转
- **单一状态中枢 + 订阅通知**（案例3 Vue reactive、案例2 Redux、案例1 provideTwinLink、案例7 DataModel）：把"选中站点/当前模块/当前年份/图层开关/评估等级"等**跨模块共享状态**收拢到一个中枢，视图订阅它自动刷新。金沙江 `G` 已扮演此角色，但缺"订阅-通知"，目前是手动 `renderPh`/`setInnerHTML`。
- **数据驱动视图**（案例7 DataModel）：`dhFetch` 结果写进一层**带缓存的 data store**，视图订阅 store，避免同一接口多处重复请求、也避免手动刷新遗漏。
- **图层配置可序列化**（案例2）：图层开关/色带/阈值/年份导出 JSON，用于论文复现与截图一致性。金沙江 `#hudLayers` 图层 chips 已有开关，但状态未序列化。

### 3.3 功能串联与联动
- **双向闭环**（案例3/案例1）：面板点选 → 3D 相机/材质更新；3D 拾取 → 状态反写 → 面板/图表高亮。金沙江 `flyToStationIdx` 是单向（面板→3D），需补**3D 拾取→图表/列表高亮**的反向链路。
- **分屏对比 + 同步导航**（案例2 split map）：多期影像、RSEI 前后期、植被变化用**双视口同步相机/时间轴**对照，比单视口切换更直观。
- **时间轴播放**（案例2/案例4）：底部时间轴 + 播放，驱动 3D 栅格着色与图表游标同步。
- **自动巡览/导览站**（案例5/案例4）：无人值守时按"导览站序列"自动飞行 + 右侧面板同步切换 + 拖拽即接管、空闲恢复。金沙江已有 `G.roaming/roamPaused`，可升级为"导览站序列"。
- **命名约定连接 3D 与业务**（案例4）：Blender 对象名 ↔ Three.js 按名改色/动画，写进约定防改坏。金沙江三维地块/站点应建立稳定的 `id` 与指标字段映射，作为评估着色的唯一钥匙。

### 3.4 渲染方式 / 性能
- **3D 克制**（案例6/案例8）：大屏核心是"数据可视化"不是"游戏美术"，砍非必要模型与特效；渲染循环只留 `controls.update + render`，其余事件触发。
- **分级画质**：金沙江已有 FPS chip，可加手动低配档（关阴影/粒子/降纹理）。
- **混合渲染防掉帧**（案例8）：2D 面板高频刷新（如每秒 KPI）不要与 3D 抢主线程，图表用独立 canvas 且按需 `setOption` 局部更新。

## 四、模块交互关系（结合金沙江现状）

金沙江前端目前的模块交互可抽象为"**交互入口 → 状态中枢 → 渲染出口**"，外加后端数据与反向联动两条副线（见图 1）：

- **交互入口**：顶栏 7 模块 nav、`#hudLayers` 图层 chips、三维 Raycaster 拾取站点、`#stationCard` 按钮、`#roamHud`、home.js 里的站点 chip / 快捷入口。
- **状态中枢**：`G`（`curPh/curModel/roaming/exag…`）+ `PH_MODULES` 注册表 + `window.STATIONS`。
- **渲染出口**：`renderPh(curPh)`（侧栏面板）、三维 render 循环（地形/河网/站点着色）、HUD 更新、`#stationCard`、toast。
- **数据副线**：`dhFetch('/api/*')` + 20s 指纹轮询 → 写状态 → 触发重绘。
- **反向联动副线**：`flyToStationIdx`（面板→3D 相机）；3D 拾取→`#stationCard`。

**现状的联动缺口**（落地建议的靶点）：
1. 3D 拾取 → 图表/列表高亮（未闭环）；
2. 3D 场景内无时间轴 → 无时序推演入口；
3. 状态更新靠手动，`switchModule` 与 `renderPh` 强耦合，新增模块要记得手动挂渲染。

## 五、落地建议

### 5.1 界面排版优化（按优先级）

1. **统一色带 Token（先做，改动最小、收益最大）**：新建 `web/assets/palette.js` 集中定义「等级色（优/良/中/差）、证据色（A/B/C/D）、风险色（高/中/低）」，CSS 变量与 JS 常量同源（`app.html` 的 `--bad/--warn/--acc` 与之对齐）。替换 `home.js` 的 `gradeCol`/`evStrip` 硬编码、`dashboard.html` 的 `kpi.up/down` 金融式色（生态看板改为"绿=改善、红=退化"语义，而非"涨红跌绿"）。改一处、三处同步。
2. **首页（态势总览）分区折叠**：保留"结论卡第一屏"，把"流域多源数据 / 指标体检 / 能力边界"收进可折叠 `<details>` 或"展开"按钮，避免 356px sidebar 内 8 区块一屏滚到底。
3. **三维主界面补"底部时序时间轴"**：在 `#bottomRow` 之上或 `#viewPane` 底部加一条时间轴通栏（拖动 + 播放），驱动 RSEI/NDVI 栅格着色，与 `dashboard.html` 年份滑块同源，打通 2D/3D 时间维度。
4. **评估模块加"向导式步骤条"**：`switchModule('assess')` 后侧栏顶部显示 5 步（选区域→选指标→一键评估→看结果→导报告），步骤态与后端评估任务绑定（衔接上一份报告的 `/api/evaluate` 数据流）。
5. **时序推演用分屏对比**：为"多期影像/RSEI 前后期"提供 split view（左三维 + 右二维栅格/ECharts），同步导航与时间轴。

### 5.2 交互改进（按投入排序）

1. **给 `G` 加轻量订阅**：不改框架的前提下，用一个小型发布-订阅（或 `Proxy` 包装 `G`）实现"状态变 → 自动刷新对应视图"，替代散落的手动 `renderPh`/`setInnerHTML`。新增模块只需声明"订阅哪些状态"，无需记住刷新时机。
2. **补反向联动闭环**：3D 拾取站点/地块后，除弹 `#stationCard`，同时高亮侧栏/图表中该站对应行（dtw-screen 的"点击建筑↔图表高亮三同步"）。
3. **图层状态序列化**：`#hudLayers` 开关 + 色带 + 年份 + 评估结果导出为 JSON，提供"导出/导入视图配置"，服务论文复现与截图一致性。
4. **自动巡览升级为导览站序列**：把现有 `roaming` 升级为"6 个导览站（如：长江第一湾→石鼓→攀枝花→溪洛渡→向家坝→宜宾），飞行停靠 + 右侧面板同步介绍 + 拖拽接管 + 空闲恢复"，用于答辩无人值守演示。
5. **数据层加缓存**：`dhFetch` 增加内存缓存（同参数不重复请求），配合指纹轮询做失效，减少重复请求与"多处各自拉同一接口"（现 home.js 的 loadNewData 一次并发 4 个 dhFetch，可合并为一个 `/api/overview` 聚合接口）。
6. **性能分级档位**：FPS chip 旁加"高/中/低"画质档，低配关闭阴影/粒子/抗锯齿，保证低配机器演示不卡。

### 5.3 一句话结论
金沙江前端的**骨架（三段式 + 面板化 + 证据分级 + 定位飞行）已经是对的**，不需要推倒重来；缺的是**"状态中枢的订阅化、色带的统一、时间轴的补位、反向联动的闭环"**这四件事。这四件事都可在现有原生 JS 架构上渐进完成，无需引入 Vue/React。
